# Claude integration selection evidence

Selection date is 2026-11-13. Repository baseline is `757aed0`. The preferred candidate is a thin adapter over the public root entry of `@anthropic-ai/claude-agent-sdk@0.3.323`. Implementation selection is blocked by the strict Node type failure and unresolved API requirements below. The SDK preserves more native control and evidence than the inspected reuse candidates. This selection does not pass the required live acceptance journeys. The unresolved requirements below block that acceptance.

The adapter supplies interfaces and native references. The host owns authorization, credential commands, writer coordination, durable intent, and reconciliation decisions. Neither the SDK's native transcript nor Switchboard is a replacement for the host's durable command log.

## Direct and LiteLLM authentication

For direct API mode, the host supplies its approved Anthropic API credential and native configuration. For LiteLLM mode, use the proxy root as `ANTHROPIC_BASE_URL` and an Anthropic Messages route. The [Claude gateway protocol](https://code.claude.com/docs/en/llm-gateway-protocol) identifies `/v1/messages`, including a `?beta=true` query, and the optional token-count endpoint. Preserve Anthropic version and beta headers, streaming events, and error responses. A proxy root already suffixed with `/v1` needs explicit URL validation to avoid an accidental double suffix.

The [LiteLLM Claude quickstart](https://docs.litellm.ai/docs/tutorials/claude_responses_api) documents proxy-root routing, static bearer credentials, and `apiKeyHelper`. LiteLLM owns upstream provider secrets. Switchboard receives only the host's proxy credential or approved credential command. Pin proxy version, route, alias-to-upstream mapping, model capabilities, and forwarded headers during live qualification. Neither an OpenAI-compatible endpoint nor a successful simple text response proves native tools, reasoning, beta features, or subagents survive.

Renewable authentication has a supported command seam. `Settings.apiKeyHelper` is public. The [settings reference](https://code.claude.com/docs/en/settings-reference#apikeyhelper) documents cached output, a five-minute default, `CLAUDE_CODE_API_KEY_HELPER_TTL_MS`, refresh after relevant 401/403 failures, and refresh before a request when a cached JWT has expired. Those refresh cases require the helper credential to be active and no overriding `ANTHROPIC_AUTH_TOKEN`. The [gateway connection guide](https://code.claude.com/docs/en/llm-gateway-connect#rotate-credentials-with-apikeyhelper) documents helper output in both Authorization and x-api-key headers. A host-owned external command is the selected renewal candidate; no IPC service or secret file is introduced.

This does not prove a host callback runs before every request. Qualify the supported TTL range, zero-TTL behavior if requested, cache invalidation, helper failure, 401/403 refresh, JWT expiry, and resumed-session refresh against the pinned binary. A callback that only resolves a credential before `query()` cannot satisfy mid-session renewal by itself. `applyFlagSettings` exposes a mid-session settings request, but its cache and in-flight auth effects are unverified and are not a renewal guarantee.

`Options.env` replaces the child environment in this pin. Use an explicit host-approved environment for each adapter, never a shared process.env mutation for proxy credentials. Native settings, helper precedence, provider flags, agents, and extensions can alter effective routing or initiate independent network requests. Report conflicts with a selected proxy policy. Do not silently disable native features or silently fall back to direct inference.

Gateway routing controls model requests, not every native network operation. The [gateway connection guide](https://code.claude.com/docs/en/llm-gateway-connect#turn-off-traffic-outside-the-gateway-path) lists nonessential-traffic controls and a separate WebFetch preflight exception. Host-enforced egress policy and native feature choices are separate from Switchboard's adapter. The [gateway overview](https://code.claude.com/docs/en/llm-gateway) does not support routing Claude Code to non-Claude models. Arbitrary cross-provider semantics and subscription forwarding are not qualified combinations.

## Reuse decision

The inspected ACP adapter does support list, load, resume, fork, and native options via metadata. Its published `NewSessionMeta` explicitly reserves permission callbacks and other options for ACP. In `dist/acp-agent.js`, its system-event switch discards task notifications, hooks, file-persistence notices, and status messages; tool progress and auth status are also discarded. Its session finder parses native storage and may search all project directories. Reusing this path would require repairing event fidelity and independently qualifying its older SDK. ACP's abstract session capabilities do not prove this adapter meets Switchboard's requirements.

The inspected AI SDK bridge can forward subagent content and some raw events. Its `dist/bridge/index.mjs` reduces init/status messages to type, subtype, and permissionMode. It defaults an omitted common permission mode to allow-all and maps that to bypassPermissions. Its package also owns sandbox bootstrap, bridge reconnection, and deferred approvals. Restoring full raw init metadata and native host policy would require changing the reuse component. Its Apache license does not remove Anthropic's underlying terms.

The direct adapter avoids these known losses and retains public native controls. It must not grow a new agent loop, workflow engine, proxy server, or native transcript rewrite layer. The existing Crew seam remains host-context evidence, not a justification for carrying Crew's service dependencies or confinement defaults into Switchboard.

## Verification and acceptance blockers

The [rerunnable probe instructions](../../spikes/claude/README.md) separate runtime fixtures from the public type check. Eight grouped fixture checks pass on macOS arm64 with Node 24.22.3. The same type fixture fails with the direct dependency versions above under the actual repository compiler gate. The diagnostic is MCP 1.32.2 `dist/esm/shared/transport.d.ts:7`, TS2304 for `HeadersInit`. No native process, helper command, provider request, production session scan, production history mutation, or credential read was performed. Synthetic transcript compatibility does not prove external CLI compatibility.

The selection task `switchboard-yejc` requires unsupported required combinations to block acceptance before implementation APIs are committed. The cached task graph assigns native direct journeys to `switchboard-ra65` and proxy journeys to `switchboard-sy8g`, after adapter integration. Their missing live evidence is not itself proof that the candidate lacks an API. These earlier selection blockers are different:

- **Compiler compatibility.** SDK 0.3.323 imports MCP's `McpServer` and therefore `shared/transport.d.ts`, even when the consumer only uses session APIs. MCP 1.32.2 refers to a global `HeadersInit` absent from Node types 24.19.2. The same declaration appears in every published peer-compatible MCP pin inspected, from 1.29.0 through 1.32.2. No safe pin or public import fix was found. An upstream declaration fix must pass the unchanged Node-only compiler policy.
- **External history classification.** The selected readers collapse some malformed and missing history into the same result. No selected public API establishes the required inaccessible, old-format, and busy outcomes. A bounded native-supported diagnostic strategy must be demonstrated before the session implementation task can rely on these helpers. Additional fixtures can investigate this without production history or model calls.
- **Externally active writers.** Host coordination covers cooperating clients, but no selected API establishes safe refusal or native coordination with an external active writer. A documented refusal mechanism or a conservative admission rule needs evidence. The plan expressly excludes a universal coordination promise with an uncooperative process; that exclusion does not authorize racing it.

The public helper command `Settings.apiKeyHelper` is a renewal candidate, not evidence that an in-process host callback runs at each request. The plan permits a host-owned credential command. Its TTL, failure, and resumed-session semantics still need bounded qualification in the proxy implementation task, followed by the live proxy journey. If that boundary cannot satisfy required renewal, the route remains blocked. Missing optional acknowledgement fields are not independently a selection blocker because the contract explicitly permits outcome-unknown without resubmission. Bounded observer delivery and AG-UI projection are adapter work, not guarantees supplied by this type fixture.

The type fixture verifies selected option values and method names. Its `Pick<Query, ...>` aliases do not verify control-call arguments, native request handling, classification, writer safety, or credential invocation timing. Successful compilation after a dependency fix would establish only declaration compatibility.

Required implementation and live follow-up evidence remains explicit:

1. Run clean packed-consumer direct and LiteLLM journeys on Linux, with separate macOS results. Record SDK/native/proxy/model versions and the source commit. Verify start, stream, native tools, native ID, teardown, and resume.
2. Create an external session with the pinned unmodified native harness in disposable state. Discover and continue it without modifying the prior prefix. Exercise unreadable, malformed, old-format, busy, and incompatible histories. Resolve the reader ambiguity without treating empty output as absence.
3. Observe the actual Messages URL, model mapping, streaming headers, and isolated proxy credentials. Rotate credentials between queries, between requests within one session, and after resume. Include helper failure and auth rejection. Confirm two concurrent adapters never share credentials and a proxy outage never causes direct inference.
4. Qualify plugins, skills, hooks, MCP, reasoning, subagents, settings precedence, and model overrides under the same direct and proxy configurations. Any required incompatible combination remains blocked.
5. Lose acknowledgement after accepted message, approval, and continuation. Interrupt the host after its callback but before durable persistence. Reconcile only from supported native evidence, otherwise return outcome-unknown without duplicate submission. Native provider retries are separate from host command retries and must be observed.
6. Cancel while streaming, waiting for permission, and running a tool. Check queued work and process exit. Test two sessions, two writers to one native ID, and slow or failed observers with bounded memory.
7. Validate projected AG-UI events against the shared pinned schema, retain raw native extensions, and test secret/error/event redaction. The SDK's raw stream is not a redacted public log.

The selection artifacts record a blocked result. Keep `switchboard-yejc` open until compiler compatibility and the two unresolved API requirements have evidence-backed resolutions. The later implementation and live journeys remain separate required gates. No requirement has been removed.
